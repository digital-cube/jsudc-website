A UDC server is a directory of collections and a few lines that serve it. This one keeps three
books in memory; swap `kind: memory` for Postgres, a directory of files or an HTTP API later
without touching the server.

<Steps>

1. Install the server, the protocol package and Fastify:

   ```sh
   mkdir books-server && cd books-server && npm init -y && npm pkg set type=module
   npm install @jsudc/server @jsudc/core fastify zod
   ```

   npm also installs `drizzle-orm` and `pg`, the server's other peers; a memory collection never
   opens a connection.

2. Lay out one collection, `books`:

   <FileTree>
   - server.ts
   - collections/
     - books/
       - schema.json the fields
       - view.yaml how the data view shows it
       - source.yaml where the rows live
       - seed.json the rows a memory collection starts with
   </FileTree>

   <Code code={schemaJson} lang="json" title="collections/books/schema.json" />

3. The server:

   <Code code={serverTs} lang="ts" title="server.ts" />

   `loadRegistry` reads every directory under `collections/`, validates its three files and
   fails at start on a mistake; `makeSource` turns each `source.yaml` into its source.
   `udcPlugin` mounts `POST /udc/<action>` on your own Fastify instance.

4. Run it and ask for the books:

   ```sh
   node server.ts
   curl -s localhost:5100/udc/list -H 'content-type: application/json' \
     -d '{"collection":"books","sort":[{"field":"year","dir":"asc"}]}'
   ```

   ```json
   {
     "kind": "udc.list.ok",
     "id": "",
     "payload": {
       "rows": [
         { "__meta": { "id": "…", "version": 1 }, "title": "The Bridge on the Drina", "year": 1945, … },
         …
       ],
       "next_cursor": null,
       "total": 3
     }
   }
   ```

</Steps>

Every answer is HTTP 200; the envelope's `kind` says `ok` or `err`. Try `describe` with
`{"collection":"books"}` to see what a client learns before it draws anything, or `mutate` to add
a fourth book: a memory collection keeps it until the process ends.
