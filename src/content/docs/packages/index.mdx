jsudc is three npm packages, one repository each. They share one version line and release
together: a client and a server speak the same protocol when their minor versions match.

<PackageTable />

0.5.0 is what a mailbox-sized UI needs. `@jsudc/core` adds the `mutate_many` action, host
actions typed end to end (`defineHostAction`), action eligibility and the `set` / `action` /
`confirm` keys of an `ActionDef`, `ListRequest.search` with the `search` capability, and the change
feed on the wire (`ChangeEvent`, `UdcClient.changes`). `@jsudc/server` serves
[`mutate_many`](/concepts/selection/#mutate_many-on-the-wire) in one transaction under the row
scope, registers [host actions](/concepts/host-actions/) with the request context, lets a source
[answer the search](/concepts/search/) (`postgres_table`'s `search`, `withSearchIndex`) and pushes
[live updates](/concepts/live-updates/) (`createChangeFeed`, `notify`, the Postgres bus).
`@jsudc/react` adds [selection and bulk actions](/concepts/selection/),
[row actions](/concepts/row-actions/), `useUdcAction`, the live provider switch with
`useUdcChanges`, and [long lists](/concepts/long-lists/) windowed in the table's infinite mode.
Every addition is optional: a 0.4.0 view, source and host work unchanged. Both `@jsudc/server` and
`@jsudc/react` 0.5.0 need `@jsudc/core` 0.5.0.

0.4.0 made jsudc what a multi-tenant host needs. `@jsudc/core` adds "not signed in" to the protocol
(`forbidden`, `reason: "unauthenticated"`), a client for cookie sessions and CSRF, and the
`postgres_table` source kind. `@jsudc/server` adds the
[request context and row scope](/concepts/request-context/), the
[`postgres_table` source](/concepts/sources/#postgres_table) with writes and `onMutate`, and the
exported SQL compiler. `@jsudc/react` adds [sessions](/concepts/sessions/),
[embedding a view](/concepts/embedding/) with a scoped stylesheet, and
[row activation and custom cells](/concepts/views/#row-activation-and-the-keyboard). Both
`@jsudc/server` and `@jsudc/react` 0.4.0 need `@jsudc/core` 0.4.0.

0.3.0 added [lookups and drill-down](/concepts/lookups/) to all three: `lookup` / `lookup_array`
fields and `row_link` in `@jsudc/core`, their filters and start-up checks in `@jsudc/server`, and
labels, chips, the combobox and `useUdcLookup` in `@jsudc/react`.

## Which ones you install

| You are writing                                  | Install                                         |
| ------------------------------------------------ | ----------------------------------------------- |
| A server that answers the UDC protocol           | `@jsudc/server @jsudc/core fastify zod`         |
| A React app over any UDC server                  | `@jsudc/react @jsudc/core` and the peers below  |
| A client in another framework, or a script       | `@jsudc/core` (its `@jsudc/core/client`)        |

`@jsudc/react` keeps its heavy dependencies as peers behind subpaths: a host that never shows a
map imports no `@jsudc/react/map` and installs no Leaflet. The
[React quick start](/get-started/react/) lists the peers each renderer needs.

## Roadmap

Phase 1, the three packages, the [live example](/examples/) and this site, is out. Phase 2 is
planned, not started:

- **More design systems.** `@jsudc/ui-mui` and `@jsudc/ui-antd`, UI kits that draw the
  renderers with Material and Ant components, each with an example route; and a headless table on
  plain HTML, built on `@jsudc/react/headless` alone. See [Theming](/concepts/theming/).
- **`@jsudc/react-native`.** The headless hooks shared with React; renderers for the table
  (FlatList), cards and calendar; the map through react-native-maps.
- **`@jsudc/angular`.** Services over `@jsudc/core/client`, a signals-based data view state, the
  table and cards components first.
- **A mobile example.** An Expo app over the backend of the live example: companies, tickets and
  flights.
