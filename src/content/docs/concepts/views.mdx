A collection's `view.yaml` is its **view**: which renderers it offers, which one opens, and how
each draws the rows. The data view (`UdcDataView` in `@jsudc/react`) draws one tab per name in
`available_renderers`; every tab shows the same rows under the same search, chips, filter and
sort, and the active tab is in the URL (`?tab=`).

```yaml
default_renderer: kanban
available_renderers: [kanban, table, cards, calendar]
kanban_options:
  bucket_collection: buckets
  bucket_filter_field: board_id
  ticket_board_field: board_id
  ticket_bucket_field: bucket_id
  card: { title_field: title, priority_field: priority, due_field: due }
calendar_options: { start_field: starts_at, end_field: ends_at, title_field: title }
```

## Seven renderers and a schema editor

| Renderer   | Draws                                                                            | Reads                                                         | Example collection |
| ---------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------- | ------------------ |
| `table`    | a grid: pinned columns, inline edit, sort by header, infinite or paged           | [`columns`, `row_color`](/reference/renderers/table/)         | `companies`        |
| `cards`    | a grid of cards: title, subtitle, image or avatar, meta fields, a metric         | [`card_options`](/reference/renderers/cards/)                 | `repos`            |
| `kanban`   | a board: columns from another collection, drag and drop, quick add               | [`kanban_options`](/reference/renderers/kanban/)              | `tickets`          |
| `calendar` | day, work week, week and month over a start and an end field, drag to move       | [`calendar_options`](/reference/renderers/calendar/)          | `appointments`     |
| `tree`     | a parent / child hierarchy, expand and collapse, drag to reparent                | [`tree_options`](/reference/renderers/tree/)                  | `org`              |
| `map`      | markers at a latitude and longitude, sized by a field, regions, trails           | [`map_options`](/reference/renderers/map/)                    | `flights`          |
| `chart`    | line, area, bar or pie over a time or category axis, with time windows           | [`chart_options`](/reference/renderers/chart/)                | `quakes`           |

The **schema editor** is the eighth view of a collection: not a tab, but the *Add column*,
*Edit column* and *Delete column* dialogs of the table header, over the
[schema revisions](/concepts/schema-revisions/) actions.

A renderer that needs fields says so in its block: the map needs `lat_field` and `lng_field`, the
kanban the fields of its columns and cards. The server validates the block at load against the
schema, so `available_renderers: [map]` without `map_options` stops the server with the reason,
and so does a block that names a field the schema does not have.

## The keys every renderer shares

- `search`: the fields the search box looks in;
- `filters`: the chips above the view (`select`, `range`, `bool`);
- `filterable`: the fields and operators of the filter builder;
- `page_size_default`, `pagination` (`infinite` or `pages`);
- `refresh_interval_ms`: poll the rows, for live data (suspended while the
  [change feed](/concepts/live-updates/) carries the collection);
- `row_link`: a click on a row opens another collection filtered by one of the row's values, see
  [Lookups and drill-down](/concepts/lookups/#drill-down-row_link).

- `multiselect`, `bulk_actions`: select rows and act on them, see
  [Selection and bulk actions](/concepts/selection/);
- `row_action_defs`, `row_actions`, `row_actions_display`: the actions of one row, see
  [Row actions](/concepts/row-actions/).

The table's infinite mode mounts only the rows near the viewport once many are loaded: see
[Long lists](/concepts/long-lists/).

Every key: [view.yaml reference](/reference/view-yaml/).

## Registering renderers

In React a host registers the renderers it shows, each from its own subpath, so a host without a
map installs no Leaflet:

```tsx
import { createRendererRegistry } from "@jsudc/react";
import { kanbanRenderer } from "@jsudc/react/kanban";
import { tableRenderer } from "@jsudc/react/table";

const renderers = createRendererRegistry(tableRenderer, kanbanRenderer);
```

A tab whose renderer is not registered is drawn disabled. A renderer of your own is one more
definition (`{ name, component, icon, labelKey, … }`); a later definition of a name replaces an
earlier one, so a host can swap the table for its own.

A renderer of your own receives `RendererProps`, a public contract from 0.4.0: see
[Embedding a view](/concepts/embedding/#a-renderer-of-the-hosts-the-rendererprops-contract).

## Row activation and the keyboard

New in 0.4.0: a row can do something of the host's, such as opening a message in a reading pane.
`UdcDataView` takes three props, all optional. Passing any of them turns activation on; without
them the rows are what they were (no tab stop, no keys, no active row, a `row_link` still
followed on click).

| Prop                     | What it does                                                                                                                                     |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| `onRowActivate(row)`     | called on Enter on a row and on a plain click of it (the main button, no modifier, not on a link, button or input in it)                         |
| `activeRowId`            | the row drawn as active. Passed: controlled (`null` for none), the host moves it in `onActiveRowChange`. Left out: the view keeps it itself (across tab switches too) |
| `onActiveRowChange(row)` | the active row changed by the user: moved by the keys (no Enter needed), or a click on another row. Preview on move here                         |

**The active row** has `aria-selected="true"`, the attribute `data-active="true"`
(`.udc-row[data-active]`, `.udc-card[data-active]` for your CSS) and the `--selected` background.
It and the focus follow the row's id across a refetch, a sort and pages loading in infinite mode;
it is scrolled into view, also when the host sets `activeRowId`. A row that left the list
(deleted, filtered out) stops being active without an error, and is active again when it comes
back.

**The keyboard**, in the table and the cards, while the focus is on a row:

| Key                 | Does                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------- |
| ArrowDown / `j`     | the next row becomes active and takes the focus; on the last loaded row in infinite mode, the next page loads and its first row becomes active |
| ArrowUp / `k`       | the previous row                                                                         |
| Home / End          | the first / last loaded row                                                              |
| Enter               | activates the row (`onRowActivate`)                                                      |
| Tab                 | the rows are one tab stop (roving `tabindex`): Tab reaches the active row, the next Tab leaves the list |

The keys are left alone while an input, the search box, a cell editor, a menu, a list box or a
dialog has the focus, and with Ctrl, Cmd, Alt or Shift held. Space is not bound unless the view
selects: from 0.5.0 it then toggles the active row's [selection](/concepts/selection/), and the
context-menu key, Shift+F10 or `.` open its [row actions](/concepts/row-actions/). The table is
`role="grid"`, the card grid too, each row or card a `row`. Double-click and Enter still edit an
editable cell when the focus is on the cell itself.

**`row_link`.** Without `onRowActivate` a click follows the view's
[`row_link`](/concepts/lookups/#drill-down-row_link) as before. With it a plain click activates
the row, and Cmd / Ctrl-click and the middle button still open the link.

## Custom cells

New in 0.4.0: a column of the table can be drawn by a component of the host's. Register cell
components by name, the way renderers are registered, and name one in the column's `render`:

```yaml
view:
  columns:
    - field: from
      render: sender # the host's component
      render_options: { avatar: true }
    - field: label
      render: badge # built in, unless the host registered "badge"
```

`render: "<name>"` resolves from the host's registry first, then from the built-in kinds (`bool`,
`badge`, `sparkline`, `heading_glyph`, `icon`, `date`, `datetime`, `number_format`, `bytes`,
`text`); a name nobody registered behaves as before. Registering a built-in name replaces that
kind for every column that names it in `render`. The cards draw their meta fields through the
same registry; the kanban, the calendar, the map and the chart keep the built-in kinds.

A cell component receives `CellProps`, a public contract like `RendererProps`:

| Prop                   | Type                    | What it is                                                                                |
| ---------------------- | ----------------------- | ----------------------------------------------------------------------------------------- |
| `value`                | `unknown`               | `row[column.field]` as the server sent it; blank values too (draw your own empty)         |
| `row`                  | `Row`                   | the whole row, `__meta` (id, version) included                                            |
| `column`               | `ColumnConfig`          | the column from `view.columns[]` (or the card's meta field): `render_options`, `align`, … |
| `def`                  | `FieldDef \| undefined` | the field's definition in the schema                                                      |
| `collection`           | `string`                | the collection's name                                                                     |
| `locale`, `intlLocale` | `string`                | the UI's language and its `Intl` locale                                                   |
| `editable`             | `boolean`               | the cell edits on double-click (the inline editor draws over your component)              |
| `surface`              | `"table" \| "card"`     | a table cell or a card's meta field                                                       |
